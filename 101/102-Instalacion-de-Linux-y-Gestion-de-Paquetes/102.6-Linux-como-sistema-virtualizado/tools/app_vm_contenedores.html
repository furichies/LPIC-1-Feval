Linux como sistema virtualizado y contenedores

Pilas VM vs contenedor y checklist post-clonado. Redacción propia.

1 Pilas de capas: VM vs contenedor

Pulsa cada capa para entender su papel. Compara el grosor de ambas pilas.

Máquina virtual

Hardware físico
Hipervisor (KVM…)
Kernel invitado propio
SO invitado + libs
App en la VM

Contenedor

Hardware físico
Kernel anfitrión (compartido)
Motor (Docker/Podman)
App + libs aisladas
Pulsa una capa para ver su explicación…
  • VM: aislamiento total, cada una con su kernel.
  • VM: más pesada; ideal para SO o kernels distintos.
  • Contenedor: comparte el kernel; aísla con namespaces + cgroups.
  • Contenedor: ligero y rápido; una imagen ocupa MB, no GB.
  • Herramientas LPIC: virsh, docker / podman.
  • Despliegue con plantillas, imágenes y cloud-init.
Para el examen: si preguntan «propio kernel» → VM · «comparte kernel / namespaces» → contenedor.
